### 3. Technologies Selected

| Layer | Selection | Rationale |
|---|---|---|
| **Framework** | Next.js 16 (App Router) | Unified fullstack runtime in TypeScript. Native API boundary (`/api/*`), server-side execution security, fast local dev without managing separate ports. |
| **Language** | TypeScript 5 (Strict Mode) | Strong type safety across provenance schemas, retrieval queries, and answer generation contracts. |
| **Styling** | Pure Vanilla CSS (`@layer`) | Zero utility CSS dependencies (no Tailwind). High performance, custom academic dark/warm palette, fluid responsive typography, and full control over layout. |
| **Architecture** | Hexagonal / Clean Core | Pure TypeScript modules in `src/core/` are isolated from Next.js and React, allowing independent unit testing and flexible backend evolution. |
| **Authentication** | None (Anonymous by Design) | Adheres strictly to the anonymous usage requirement. |

### 5. Assumptions Made

1. **Single Runtime Fullstack Monorepo**: Selected Next.js with an isolated `src/core/` domain layer rather than a split Node + Python monorepo for Segment 0. This ensures zero friction for developers while maintaining clear architectural boundaries. Heavy offline ingestion scripts in later segments can be placed in `scripts/` (e.g. Python scripts for PDF OCR or chunking) without complicating the web app runtime.
2. **Anonymous Session Handling**: Assumed that session identification for rate-limiting will be ephemeral (cookie-less or client-generated token with IP-based fallback) so that user privacy is strictly preserved.
3. **Primary Source Scope**: Formally codified the 6 approved primary source categories in `src/core/sources/types.ts` and restricted the author field strictly to `"B. R. Ambedkar"`.
